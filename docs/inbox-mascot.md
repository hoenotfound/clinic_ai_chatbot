# Dashy floating Inbox companion

The ten official 160 × 160 transparent WebP expressions remain unchanged. Sleeping and Interactive have no artwork in the supplied PDF. Dashy is a single transparent overlay inside the Inbox, not a header item, and has no effect on the underlying layout. Default artwork canvas: 100px for large workspaces, 85px for tablet-width workspaces and 65px on narrow screens. Settings and quick controls offer Auto, Small, Medium, Large.

Drag using native pointer events (mouse, touch, pen); release saves a normalized browser-local position. Arrow keys move the focused mascot (Shift for larger steps); Enter/Space or click opens controls. Dragging suspends motion and is distinct from a tap. A cancelled drag restores the saved position. The rest position is clamped within the Inbox and moved to the nearest available location away from the search/list header, chat header and composer. It temporarily disappears if no safe position exists. The surrounding overlay is pointer-transparent. Existing dialogs stack above it, and known contact/template/composer dialogs suspend it. Resize, orientation and changing conversation layout recompute safe positioning; no polling. Dragging over ordinary conversation content is intentional, but the resting mascot can obscure some message text, so reposition or hide it as desired.

Animated, Stationary and Hidden modes are retained. Click Dashy for pause/resume, size, reset and hide; restore a hidden mascot from Settings → Appearance. Position and size persist on this browser. Reduced motion disables animation. A brief greeting on entry, actual selected-thread message, failure, and verified staff booking reactions remain. Searching uses the existing list request. Thinking is preview-only. Desktop roaming begins after 75 seconds of inactivity and returns to the saved location; mobile has no autonomous roaming. Typing, recording, sending, menu interaction, dragging and background tabs suppress decorative movement. No new backend queries, AI calls, SSE connections or libraries. Static assets load from the existing build.

Verify pointer and keyboard movement, touch dragging, resize/orientation, persistence, reset, menu dismissal, visibility, no header/composer overlap, mobile layout, modal stacking, reduced motion, official expressions, and existing message/booking reactions. No live deployment is implied by this branch.

Refinements: the transparent corners pass input through via an elliptical touch region (not exact per-pixel alpha). Dragging writes CSS transforms at most once per animation frame; persisted coordinates change only on release or keyboard movement. Visual viewport intersection protects against zoom/panning and software keyboards. The quick menu selects unobstructed space and scrolls if needed; when no usable menu fits, tapping opens Appearance. The resting character dims during reading/typing and returns to full opacity on interaction; first-use hint is browser-local. Desktop flight uses a computed safe rectangular path around the saved location, not an unrestricted flight across the Inbox. Browser tests cover CDP touch input, rotation-like viewport changes and a simulated keyboard viewport; physical iOS/Android device checks remain necessary.

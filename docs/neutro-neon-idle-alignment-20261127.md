# Neutro November compute protection

Opt in on Neutro production only after full CI and review:
- NEUTRO_IDLE_MAINTENANCE_ALIGN_ENABLED=true
- META_AD_INSIGHTS_SYNC_MS=21600000 (six-hour analytics sync; existing setting)

Empty recovery sweeps with an existing 30- or 60-minute backstop align within the same 45-second UTC hour/half-hour window (also MYT clock boundaries). Named workers have distinct fixed offsets to reduce simultaneous SQL bursts; urgent events and stored deadlines bypass the offsets. This is scheduling, not a concurrency limit. A long-running sweep may still overlap another worker. Round down from the original maximum deadline, never extend it. A newly empty worker can run an earlier one-time sweep before settling into alignment. The flag defaults off. Only explicit idle paths are changed: generic idle recovery, strict RM0 result queue, secondary media with no pending/claimed jobs, delivery-status idle recovery after startup recheck, comment recovery without a deadline and extended FEP idle scheduling. Active jobs, exact due times, immediate event wakes, errors, stale leases and provider/billing gates remain unchanged. No worker is disabled. The customer media cleanup worker aligns only its idle fallback; its ten-minute startup grace, known purge deadlines and error retries remain unchanged. The Meta Ads Insights, customer retention and completed purge-job prune periodic schedulers share the same windows, retain their individual recurring cadence, and may run their first scheduled maintenance up to one hour earlier than the normal interval; this is never an immediate retention/prune startup sweep. The flag defaults off for other deployments.

Extended FEP scheduler checks the same runtime quiet-hour configuration used by its final send guards before scanning. Config changes already wake the scheduler, and it rechecks on every wake. At reopening fresh candidate selection and all existing send checks execute. Direct run() calls and actual send guards remain unchanged. Overnight skip reporting will no longer be generated by scheduled sweeps while sending is prohibited.

CI must exercise the opt-in path, including actual idle recovery timer execution, pending work and failures, immediate appointment recovery, real extended scheduler subscription wakes and quiet-hour reopening, media/billing retries and periodic maintenance offsets. Use the existing Render deployment process only after CI; combine environment settings with the release rather than deploy repeatedly. No schema migration or production SQL needed. Compare Neon management API CU-hours and start/suspend operations over equal traffic periods and passive Render pool logs. Verify normal reply, queued media, billing receipt recovery, appointment recovery, FEP delivery timing, comment recovery and quiet-hour reopening. Disable the alignment flag or revert to the previous commit if recovery regresses; restore the Insights interval to 3600000 if hourly reporting is needed. Do not claim measured CU savings until observed.
